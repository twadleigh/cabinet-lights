## Settled Constraints

- Pico 2 W and existing SRAM are fixed; no replacement/PSRAM. **SD is dropped**, revisit only if the user explicitly raises it in the distant future. No reader/pins/SD capture/updater work.
- Retain PlatformIO + Arduino-Pico; native SDK migration is not selected. Preserve AGENTS.md pinout, I2S framing and core ownership. New filenames use snake_case where naming is unconstrained; dependency/tool-required names may differ.

## Next: Bench and Remaining Decisions

Follow [doc/bench_validation.md](doc/bench_validation.md) in order; record evidence, not just a pass label.

1. **R02 power isolation:** unpowered inspection first. Identify actual buck/controller and trace reverse-current path; `4R7` is only an inductor marking. Establish external-source isolation/ORing and buffer voltage requirements before USB-only/external-only/combined-power measurements. Neither boot success nor telemetry proves no backfeed. No physical remedy has been selected/installed by this change.
2. **R03 reset/off state:** establish existing buffer input bias/OE wiring; measure outputs/gates during startup, reset, shutdown and safely prepared absent-MCU conditions. Consider input pull-downs or controlled OE without GPIO reassignment if measurements require them. Gate pull-downs alone do not override an active HIGH output.
3. **R08 contacts:** continuity-test each reed with magnet near/away; record exact installed part if identifiable. Firmware active-LOW semantics remain unchanged.
4. Deploy via an understood power path with USB recovery available, then check new identity, controls, mic envelope, OTA success and interrupted/abandoned-transfer recovery. Run the finite 30-minute software soak with deliberate inputs and Wi-Fi loss; record duration and unexplained resets/faults/stalls. Current sensors cannot measure strip current, external temperature or waveform; full-load electrical/thermal acceptance requires instruments and actual load.
5. **T04 optional password:** retain existing credentials. If nonempty, test correct/missing/wrong uploader password, firmware unchanged on rejection, audio recovery and immediate correct retry. If disabled, explicitly leave protected-board acceptance pending. Useful basic home-LAN protection, not encryption or strong firmware authenticity; separate PREP is unauthenticated. Do not silently enable/rotate credentials.
6. **Model/storage:** after candidate export, measure flatbuffer, arena/operators, preprocessing and worst-case RAM/latency. Evaluate larger internal staging and actual compression before choosing a map; neither is selected. Separate reserved mapped-flash model updates remain possible but require an installer, layout migration and explicit power-loss recovery. Single-slot replacement can lose classification until re-upload; preserve Normal/Debug and firmware recovery. Retaining old model needs another slot. Do not promise every SRAM-compatible model fits active flash plus robust staging. No SD work.
7. Phase 3: implement DF2T IIR/AGC/envelopes/spatial mapping. Phase 4: UDP capture, training/runtime golden fixtures, schedulable inference and model deployment. These are not incidental review cleanup.
